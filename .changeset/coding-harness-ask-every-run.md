`coding-harness` asks sections A–G on every run, in one list, and shows the last answer or the recommendation. A section left untouched keeps that shown answer, and `phases.md` is copied before the reply. Section G records the phase doors (`plan`, `design`, `build`, `deploy`, `operate`) plus the context, in place of a single default skill. The validation command is run on that run. An existing harness keeps repo lines the template does not have, such as a branch guard or a Stitch block.
